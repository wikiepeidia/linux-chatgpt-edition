<interfaces>
Create and freeze these contracts before the real gate:

- `Start-CheckedProcessLease -FilePath <string> -ArgumentList <string[]> -TimeoutSeconds <int> ...` returns the exact owned `System.Diagnostics.Process`, asynchronous stdout/stderr drains, bounded wait/stop operations, and an idempotent dispose operation. `Invoke-CheckedProcess` uses the same primitive for short-lived commands.
- `KeyInitRequest` contains operation, schema, target identity label, Alpine/cloud-image/script pins, and run nonce only. It contains no signing-public hash because that identity does not exist until initialization returns `signing-public.json`.
- `BuildRequest` is created only after `signing-public.json` is independently validated. It contains only known content inputs: target/arch, clean source archive and hash, fixed epoch, input/script/profile hashes, aports commit, approved repository-index hashes, requested package names, public-key basename/hash, and canonical guest roles.
- `ResolvedBuildLock` is emitted by `run-build.sh` after resolution. It records the BuildRequest hash, exact signed indexes, complete retained APK closure, exact installed builder manifest, verified aports bytes, pinned inspection package/APK facts, resolved decoder paths and normalized versions, and generated output references. It is never used to mutate the already-dispatched BuildRequest.
- Generated ownership: `build.ps1` produces `build-request.json`; `run-build.sh init-signing-key` produces `signing-public.json`; `run-build.sh prepare-repository` produces `resolved-build-lock.json`, `builder-packages.lock`, and `apk-files.sha256`; `build.ps1` validates each schema/hash/reference before publication.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Windows parameters/Git → `build.ps1` | Untrusted paths and repository bytes become immutable requests only after clean-state and canonical-path checks. |
| Host → owned QEMU guest | Public seed data, exact request/source bytes, one ephemeral SSH identity, and external APK identity cross a loopback-only boundary. |
| Serial channel → SSH trust store | A public Ed25519 host key/fingerprint becomes the sole run-local trust anchor. |
| Alpine HTTPS → retained local repository | Mutable upstream indexes/packages are admitted only after signature/hash verification and content addressing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-P1-01 | Spoofing | QEMU SSH endpoint | high | mitigate | Derive Ed25519 public key/fingerprint from the owned serial channel, prepopulate the exact loopback endpoint, ignore ambient config/agents/proxies, and require strict checking. |
| T-01-P1-02 | Tampering | Native process lifecycle | high | mitigate | Use ArgumentList, exact Process ownership, async drains, finite deadlines, child-tree-only stop, and idempotent lease disposal. |
| T-01-P1-03 | Tampering | APK/aports repository | high | mitigate | Verify signed fixed indexes and every retained APK/aports byte, install from a content-addressed file-only repository with network disabled, and recheck before/after use. |
| T-01-P1-04 | Information Disclosure | APK/SSH private material | high | mitigate | Keep identities outside Git, transfer through bounded inputs to guest tmpfs, publish only public hashes, redact before persistence, and clean in one outer finally owner. |
| T-01-P1-05 | Repudiation | Backend execution status | medium | mitigate | Bind status to real child exit codes and evidence hashes; Docker remains unverified when no daemon runs and fixtures cannot create executed status. |
| T-01-P1-06 | Denial of Service | QEMU/network/build stages | medium | mitigate | Apply finite stage-specific deadlines, preserve sanitized serial evidence, stop only owned resources, and retain the prior completed artifact pointer. |
</threat_model>
